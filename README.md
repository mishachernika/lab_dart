## Мета роботи

Створити консольний застосунок мовою Dart, описати предметну область класами, отримувати дані з відкритого REST API, зберігати їх у локальному JSON-файлі та відновлювати під час наступного запуску. Додатково реалізувати пошук, фільтрацію, сортування та модульні тести.

## Опис застосунку

Застосунок веде локальну колекцію покемонів. Користувач може додати покемона вручну або завантажити його за ім’ям чи ID із PokéAPI. Колекція зберігається у `data.json`, тому додані записи залишаються доступними після завершення програми.

### Можливості

- перегляд колекції покемонів;
- додавання запису вручну або завантаження з API;
- видалення покемона з колекції;
- пошук за частиною імені без урахування регістру;
- фільтрація за типом покемона;
- сортування за ID, ім’ям, зростом, вагою або базовим досвідом;
- створення тренерів і призначення їм покемонів із колекції;
- збереження даних у JSON та відновлення під час запуску;
- обробка помилок мережі, відповіді сервера та локального файлу.

## Використане API

Для варіанта 6 використано відкритий REST API [PokéAPI](https://pokeapi.co/), який не потребує ключа авторизації.

**Приклад запиту:**

```text
https://pokeapi.co/api/v2/pokemon/pikachu
```

Замість `pikachu` можна передати ID, наприклад `25`. З відповіді застосунок читає ID, ім’я, зріст, вагу, базовий досвід і перший тип покемона.

**Скорочений приклад відповіді:**

```json
{
  "id": 25,
  "name": "pikachu",
  "height": 4,
  "weight": 60,
  "base_experience": 112,
  "types": [
    {
      "slot": 1,
      "type": { "name": "electric" }
    }
  ]
}
```

API-клієнт перевіряє HTTP-статус і перетворює JSON на модель `Pokemon`. Якщо покемона не знайдено, сервер повернув помилку, запит завершився тайм-аутом або відповідь має некоректний формат, застосунок показує повідомлення та продовжує роботу з локальною колекцією.

## Основні програмні рішення

- **Моделі.** `Pokemon`, `Trainer` та `AppData` описують дані застосунку. Моделі реалізують `Storable` і надають метод `toJson()`; фабричні конструктори `fromJson()` відновлюють об’єкти з JSON.
- **Перелік типів.** `PokemonType` зберігає тип покемона як `enum`. Невідомий API тип можна представити значенням `other`.
- **Зв’язок моделей.** Тренер зберігає ID покемонів. Під час видалення покемона його ID також видаляється зі списків тренерів.
- **API-сервіс.** `PokemonApi` використовує `package:http` та приймає `http.Client` через конструктор. Це дає змогу підмінити мережевий клієнт заглушкою `MockClient` у тестах.
- **Репозиторій.** `DataRepository` відповідає за читання та запис `data.json` і повідомляє про пошкоджений JSON або помилки файлової системи.
- **Пошук і сортування.** Функції з `pokemon_queries.dart` повертають результати пошуку, фільтрації та сортування колекції.
- **Перевірка введення.** Консольне меню перевіряє числові значення та повідомляє про некоректне введення.

## Запуск

Потрібен встановлений [Dart SDK](https://dart.dev/get-dart). У кореневій теці проєкту виконай:

```bash
dart pub get
dart run bin/main.dart
```

У меню вибери пункт **3**, введи ім’я або ID покемона, наприклад `pikachu`, а потім переглянь колекцію пунктом **1**. Для перевірки збереження заверши програму через **0** і запусти її знову. Дані зберігаються у `data.json` у теці запуску; цей локальний файл виключений із Git через `.gitignore`.

## Тестування та аналіз

Модульні тести запускаються командою:

```bash
dart test
```

На момент підготовки цього README команда завершилася успішно: **усі 25 тестів пройшли**. Тести перевіряють серіалізацію моделей, розбір відповіді PokéAPI, збереження даних, пошук, фільтрацію, сортування та обробку помилок. Для API використовується `MockClient`, тож мережевий запит під час цих тестів не потрібен.

Форматування й аналіз коду:

```bash
dart format .
dart analyze
```

Під час попередньої перевірки `dart analyze` завершився повідомленням `No issues found!`.

## Висновок

У лабораторній роботі створено консольний застосунок на Dart для ведення колекції покемонів. Реалізовано класи предметної області, перелік типів, обмін даними з PokéAPI, серіалізацію та збереження JSON-файлу, пошук, фільтрацію, сортування й модульні тести. Під час роботи закріплено використання колекцій, `async`/`await`, обробки помилок і розділення програми на моделі, сервіс та репозиторій.
