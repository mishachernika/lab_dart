Консольна програма на Dart для ведення колекції покемонів. Покемона можна додати вручну або завантажити з [PokéAPI](https://pokeapi.co/). Колекцію можна переглядати, шукати, фільтрувати й сортувати. Дані зберігаються у `data.json`, тому залишаються після повторного запуску.

## Запуск

Потрібен встановлений Dart SDK. У терміналі відкрий папку проєкту й виконай:

```bash
dart pub get
dart run bin/main.dart
```

Після запуску з’явиться меню. Щоб завершити роботу, введи `0`.

## Пункти меню

| Пункт | Що робить |
|---:|---|
| `1` | Показує покемонів у колекції |
| `2` | Додає покемона вручну: ID, ім’я, зріст, вагу, досвід і тип |
| `3` | Завантажує покемона з PokéAPI за ім’ям або ID |
| `4` | Видаляє покемона за ID |
| `5` | Шукає за ім’ям або його частиною |
| `6` | Фільтрує список за типом покемона |
| `7` | Сортує за ID, ім’ям, зростом, вагою або досвідом |
| `8` | Відкриває меню тренерів |
| `0` | Виходить із програми |

У меню тренерів можна переглянути тренерів, додати нового та призначити йому покемона з колекції.

## Приклади

Завантажити Пікачу можна через пункт `3`, ввівши `pikachu` або `25`. Для перегляду результату обери пункт `1`:

```text
Оберіть пункт: 3
Імʼя або ID покемона (наприклад, pikachu або 25): pikachu
Отримано з API й додано: #25 pikachu [electric] зріст: 4, вага: 60, досвід: 112
```

Також покемона можна додати без інтернету через пункт `2`. Наприклад, після введення даних програма покаже його в колекції.

Для завантаження з API потрібен інтернет. Якщо покемона не знайдено або запит не вдався, програма виведе повідомлення про помилку.

## Файл з даними

Програма читає й записує файл `data.json` у кореневій папці проєкту. У ньому зберігаються покемони та тренери. Якщо файла ще немає, застосунок починає з порожньої колекції.

`data.json` записаний у `.gitignore`, тому локальні дані не додаються до GitHub.

## Структура проєкту

```text
lab_dart/
├── bin/
│   └── main.dart                 запуск і консольне меню
├── lib/
│   ├── lab_dart.dart             експорти проєкту
│   ├── models/                   Pokemon, Trainer, AppData, PokemonType
│   ├── repositories/             робота з data.json
│   └── services/                 PokéAPI, пошук, фільтр і сортування
├── test/                         автоматичні тести
├── docs/screenshots/             приклади запуску й перевірок
├── analysis_options.yaml         правила аналізатора
├── pubspec.yaml                  налаштування та залежності
└── README.md
```

Моделі зберігаються в `lib/models/`, HTTP-запит винесений у `lib/services/pokemon_api.dart`, а читання і запис файла — у `lib/repositories/data_repository.dart`.

## Що використано в роботі

- класи `Pokemon`, `Trainer` та `AppData`;
- `enum PokemonType` для типів покемонів;
- `final`, іменовані та фабричні конструктори;
- JSON-серіалізація через `toJson()` і `fromJson()`;
- `Future`, `async` і `await` для запиту до API та роботи з файлами;
- пакет `http` для HTTP-запитів;
- колекції Dart для пошуку, фільтрації та сортування;
- обробка помилок запиту, введення та читання даних.

## Тести й аналіз коду

Запустити тести:

```bash
dart test
```

Перевірити стиль форматування та статичний аналіз:

```bash
dart format .
dart analyze
```

Під час останньої перевірки всі **25 тестів пройшли**, а `dart analyze` завершився без зауважень. Тести перевіряють моделі, JSON, файл із даними, пошук і сортування, а також різні відповіді API. Для API використовується `MockClient`, тому ці тести не залежать від доступу до інтернету.

Окремо меню перевірялося вручну: перегляд списку, додавання, завантаження з API, видалення, пошук, фільтр, сортування та робота з тренерами. Також перевірялося, що зміни залишаються після перезапуску програми.
