# Лабораторна робота 1–2 — колекція покемонів на Dart

Привіт! Мене звати **Чернік Михайло Богданович**, я студент 4 курсу спеціальності **Інженерія програмного забезпечення (ІПЗ)**. У цій лабораторній я зробив консольний застосунок для роботи з колекцією покемонів. Мій варіант — **№ 6**.

Програма запускається в терміналі. У ній можна додавати покемонів вручну або завантажувати їх з PokéAPI, шукати, фільтрувати й сортувати список, а також створювати тренерів і призначати їм покемонів. Дані зберігаються у файл `data.json`, тому після повторного запуску колекція відновлюється.

## Що потрібно для запуску

- Dart SDK;
- підключення до інтернету, якщо потрібно завантажити покемона з PokéAPI.

Перейди в папку проєкту та виконай команди:

```bash
dart pub get
dart run bin/main.dart
```

Щоб закрити програму, введи `0` у головному меню.

## Що вміє програма

У головному меню доступні такі пункти:

| № | Дія |
|---:|---|
| 1 | Показати покемонів, які вже є у колекції |
| 2 | Додати покемона вручну: ввести ID, ім’я, зріст, вагу, досвід і тип |
| 3 | Завантажити покемона з PokéAPI за ім’ям або ID, наприклад `pikachu` чи `25` |
| 4 | Видалити покемона за ID |
| 5 | Знайти покемонів за повним ім’ям або його частиною |
| 6 | Показати покемонів вибраного типу |
| 7 | Відсортувати список за ID, ім’ям, зростом, вагою або досвідом |
| 8 | Перейти до меню тренерів |
| 0 | Завершити роботу |

У меню тренерів можна переглянути список тренерів, додати тренера та призначити йому покемона з колекції. Програма перевіряє введення, попереджає про повторний ID і показує повідомлення, якщо потрібний запис не знайдено.

## Як отримуються дані

Для завантаження покемона використовується відкритий API [PokéAPI](https://pokeapi.co/). Наприклад, для Пікачу програма звертається за адресою:

```text
https://pokeapi.co/api/v2/pokemon/pikachu
```

З відповіді програма бере ID, ім’я, зріст, вагу, базовий досвід і тип. Якщо сервер повернув помилку або покемона не знайдено, застосунок повідомляє про це в терміналі.

## Як зберігаються дані

За читання та запис відповідає `DataRepository`. Під час запуску програма читає `data.json`, якщо такий файл існує. Коли колекція або список тренерів змінюється, нові дані записуються у JSON. Якщо файла ще немає, програма починає з порожньої колекції.

Файл `data.json` доданий до `.gitignore`: мої локальні записи не потрапляють до GitHub разом із кодом.

## З чого складається проєкт

```text
lab_dart/
├── bin/
│   └── main.dart                  запуск програми та консольне меню
├── lib/
│   ├── lab_dart.dart              експорти проєкту
│   ├── models/                    моделі покемона, тренера та даних
│   ├── repositories/              читання і запис data.json
│   └── services/                  PokéAPI, пошук, фільтр і сортування
├── test/                          автоматичні тести
├── docs/screenshots/              приклади роботи та результати перевірок
├── analysis_options.yaml          налаштування аналізатора
├── pubspec.yaml                   налаштування Dart-пакета
├── pubspec.lock                   зафіксовані версії залежностей
└── README.md                      цей опис
```

У проєкті є класи `Pokemon` і `Trainer`, перелік `PokemonType`, клас `AppData` для роботи з колекціями та `Storable` для серіалізації. Код розділено на моделі, сервіси й репозиторій, щоб кожна частина відповідала за свою задачу.

## Перевірка програми

Щоб запустити автоматичні тести й перевірити код, виконай:

```bash
dart test
dart analyze
```

У моїй перевірці пройшли **25 тестів**, а команда `dart analyze` завершилася повідомленням `No issues found!`. Тести перевіряють моделі, JSON, збереження даних, пошук, фільтр, сортування та відповіді API. Для API-тестів використовується MockClient, тож їм не потрібно звертатися до справжнього сервера.

Також я вручну перевірив роботу пунктів меню `1–8`: показав колекцію, додав і видалив тестового покемона, завантажив Bulbasaur з API, виконав пошук і фільтр, відсортував список, створив тренера та перевірив збереження після повторного запуску. Окремо перевірив некоректне введення, дубль ID і відповідь API 404.
